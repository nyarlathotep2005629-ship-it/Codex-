# WorkoutTracker v1.0 UIデザイン参考

基準: ユーザー提供のWindowsダッシュボード画像とAndroid 3画面画像（2026-11-03）。画像は視覚・情報配置の参考であり、表示されている数値や機能の仕様を追加するものではない。

## 共通ルール

- 黒からチャコールの背景、やや明るいカード面、細い境界線で階層を作る。
- 主操作と選択状態はティール／シアン、達成や補助的な強調はライムを使う。意味を色だけに依存させず、文字や状態も併記する。
- 画面先頭に現在の目的を示し、主要な数値・予定・次の操作を視線の流れに沿って配置する。
- 種目・セット・予定・統計はカード単位に分け、十分な余白とタッチ領域を確保する。
- RM／RPEの説明は該当する値や入力欄の近くに置く。
- グラフは軸、単位、対象種目、期間を読み取れるようにする。実データがない場合は空状態を示す。
- 参考画像の架空の記録、週間達成率、連続日数、栄養機能、目標重量は、根拠となる実装・データがない限り表示しない。

## Windows

- 既存の左ナビゲーションを活用し、ダッシュボード・ワークアウト・履歴・カレンダー・統計・トレーニングデータ・週間メニューへ到達しやすくする。
- 広い領域では概要カードと詳細カードを並べる。操作表や入力欄は横幅を使い、キーボード・マウス操作とフォーカス表示を維持する。
- 今日の予定、実際の履歴、統計は別の情報として明示する。

## Android

- ホーム、記録、統計を優先し、主要操作は片手で押しやすい高さと余白にする。
- 種目選択は検索と主部位フィルターを先に置き、長い一覧はスクロール可能なカードで示す。
- セット入力は重量・回数・RPEの対応を崩さず、追加・保存・次の操作を明確にする。
- 週間メニューは曜日と休息日を一目で判別でき、対象日から記録へ進めるようにする。

## 適用時の確認

Windows WPFとAndroid MAUIで同じ機能の意味を保ちながら、それぞれの画面幅と操作方法に合わせる。小画面、表示倍率、文字切れ、コントラスト、フォーカス、空状態、エラー状態を実画面で確認する。未実施の確認はPASS扱いしない。
